# Source Whitelist Audit Prompt — Goggle Output

## Usage

Replace `{{COUNTRY}}` and `{{COUNTRY_CODE}}` (ISO 3166-1 alpha-2) with the target country. Provide the country's existing source whitelist document as input context.

This prompt runs a single-pass audit combining two expert perspectives:
- **Pipeline utility** (Section 20): What priority should each source receive when the pipeline queries for this country's news?
- **Ecosystem coverage** (Section 10): Does the overall source map capture how information actually flows in this country?

The output is a boost-weight assignment for every source (recommended, excluded, and newly identified), a structural gap analysis, a query configuration, and a ready-to-use Brave Search Goggle file.

### Architecture context

The source whitelist being audited was generated by a **curation prompt** that assumed a hard-filter pipeline model: "sources not on the whitelist are discarded before analysis." The pipeline has since migrated to the **Brave Search News API** with per-country **Goggles** — Brave's domain-specific ranking overlays. This changes the filtering paradigm:

- **Old model (curation prompt):** Binary include/exclude. Sources not on the whitelist are invisible to the pipeline. The curation prompt targeted 15–20 sources with an expected trim to 8–12 after extractability testing.
- **New model (Goggles):** Tiered boost/neutral/discard. Boosted sources surface first; non-boosted sources can still appear organically if Brave ranks them highly for a specific query; only explicitly discarded sources are removed. There is no source count constraint.

Instead of querying each source individually, the pipeline runs **topic-based queries** (e.g., `"Keir Starmer defence spending"`) through the News Search endpoint with:
- `country` and `search_lang` parameters to localize results
- `freshness=pw` (past week) for weekly pipeline cycles
- A country-specific Goggle that boosts whitelisted sources, discards known noise, and lets everything else rank naturally

This means **source count does not drive API cost** — whether a Goggle contains 12 or 25 boost rules, the number of API calls stays the same. What matters is: (a) the boost weights correctly prioritize high-signal sources, (b) known noise sources are discarded, and (c) the structural coverage has no blind spots that would cause the pipeline to miss significant events.

### Input document structure

The source whitelist you are auditing follows a fixed structure produced by the curation prompt. Each recommended source includes the following fields, which you should validate and build upon:

| Field | Use in audit |
|---|---|
| **Type** | One of: `paper_of_record`, `business_financial`, `security_defense`, `political_specialist`, `opposition_aligned`, `government_aligned`, `regional`, `investigative`, `legislative_official`. Use this classification to inform boost assignments — `legislative_official` and `security_defense` sources earn boost through structural role; `opposition_aligned` sources earn boost because the pipeline needs to see domestic contestation. Correct misclassifications where you find them. |
| **Domain Coverage** | Maps to the five analytical domains. Validate these claims — a source listed for "Security & defence" that actually publishes primarily domestic political commentary is miscategorized. |
| **Editorial Orientation** | Ownership, political lean, relationship to government. Refine these into pipeline-ready source-weighting statements in the Interpretive Context output section. |
| **Why This Source** | The curation prompt's justification. Pressure-test this — does the stated gap-fill hold up, or is the source redundant with another? |
| **Access Notes** | Paywall/scraping status. Under the Goggle model, hard paywalls are less of a concern for *discovery* (Brave indexes paywalled content for ranking) but still matter for *extraction* (Diffbot may not get full text). Flag but don't auto-discard. |

The whitelist also includes a **Notable Exclusions** section, a **Coverage Gap Assessment**, and a **Localized Query Vocabulary** section with 5–8 search terms per analytical domain. The query vocabulary should be referenced and validated in the Query Configuration output, not regenerated from scratch.

## Prompt

You are conducting a **source whitelist audit** for the Middle Powers Monitor (MPM), an automated intelligence pipeline that tracks democratic leaders defending the liberal international order amid US retrenchment.

You are reviewing the source whitelist for **{{COUNTRY}}**. The whitelist was generated by an LLM and has not yet been validated by a domain expert. Your task is to assess every recommended source and every notable exclusion, identify any missing sources, assign boost weights, and produce a ready-to-use Brave Search Goggle file.

### Your Expert Perspectives

You are simultaneously applying two analytical lenses:

**Lens 1 — Pipeline Signal Prioritization (computational social scientist + intelligence fusion analyst)**
The pipeline runs topic-based queries through Brave's News Search API with a country-specific Goggle applied. Higher-boosted sources surface first in results. Your boost assignments determine what the pipeline sees first — and what it sees at all. A source that produces original reporting on defence policy decisions deserves a higher boost than one that syndicates wire copy with light editorial framing. A source that functions as the government's preferred leak channel deserves a high boost not because it's trustworthy, but because its content is a primary signal of government intent.

**Lens 2 — Media Ecosystem Coverage (comparative media systems scholar)**
The Goggle must capture the actual information architecture of the country. This means ensuring that structurally important outlets receive boosts — including outlets that aren't "good journalism" but serve essential signaling functions (government mouthpieces, opposition organs, defence-sector trade press). It also means identifying noise sources that should be actively discarded to prevent them from consuming result slots that higher-value sources should fill.

### The Five Analytical Domains

Sources earn boost weight by covering one or more of these domains with material the pipeline can't reliably get elsewhere:

1. **Diplomatic alignment** — Foreign policy positioning, bilateral/multilateral engagement, alliance signals
2. **Security & defence autonomy** — Military posture, defence spending, security cooperation, arms procurement
3. **Economic & technological statecraft** — Trade policy, sanctions, investment screening, technology regulation, industrial strategy
4. **Institutional engagement** — UN/EU/NATO/regional body participation, treaty compliance, institutional reform posture
5. **Domestic constraints on external action** — Parliamentary opposition, public opinion, coalition dynamics, fiscal pressure that constrains foreign/defence policy

### Boost Weight Scale

Assign each source exactly one of the following:

| Weight | Goggle rule | Meaning | Criteria |
|--------|-------------|---------|----------|
| **Tier 1** | `$boost=3` | Essential — surface first | Produces original reporting in ≥2 analytical domains; unique structural role (paper of record, government gazette, top defence/security outlet); content regularly unavailable elsewhere |
| **Tier 2** | `$boost=2` | Important — surface prominently | Strong on 1–2 specific domains; fills a distinct editorial lens (opposition voice, investigative, specialist); not fully redundant with any Tier 1 source |
| **Tier 3** | `$boost=1` | Supplementary — surface when relevant | Useful perspective or domain niche; some overlap with higher-tier sources but adds interpretive diversity or occasional unique reporting |
| **Neutral** | *(no rule)* | Organic ranking | Not worth boosting, but not harmful. Under the old hard-filter model, these sources were excluded entirely. Under the Goggle model, they can still surface when Brave ranks them highly for a specific query — which means they may contribute serendipitous signal the pipeline wouldn't otherwise see. **Default the curation prompt's "Notable Exclusions" to neutral unless they meet the Discard criteria below.** |
| **Discard** | `$discard` | Actively remove from results | Reserve `$discard` for sources that would actively degrade results: tabloids that sensationalize without reporting, content farms, known misinformation outlets, and pure aggregators whose presence would displace a boosted source from the top 20 results. **Do not discard a source merely because it wasn't selected by the curation prompt.** A source must be positively harmful to result quality to earn `$discard`. |

**Boost assignment principles:**
- **Structural role outweighs journalistic quality.** A government-controlled outlet that signals policy intent gets Tier 2 even if its journalism is propagandistic — the pipeline needs the signal, and the dossier's source-weighting context tells the LLM how to interpret it.
- **Source type informs tier floor.** The curation prompt's `type` field maps to minimum expected boost levels: `security_defense` → Tier 1–2 (specialist signal); `opposition_aligned` → Tier 2–3 (contestation signal); `paper_of_record` → Tier 1–2 (agenda-setting); `business_financial` → Tier 2 (economic statecraft signal). These are starting points — override based on actual assessment.
- **Official government sources are migrating to Layer 2 (direct fetch).** Sources typed as `legislative_official` or `government_aligned` in the curation prompt (e.g., GOV.UK, Hansard, ministry press offices) are being moved to a separate direct-fetch pipeline that polls known URLs on a schedule rather than relying on Brave Search discovery. **Flag these sources as `LAYER 2 MIGRATION` in the audit.** They should still receive a Goggle boost rule as a belt-and-suspenders measure (government press releases occasionally appear in Brave News Search), but the primary fetch path will be direct polling. Assign them Tier 2 in the Goggle and note the Layer 2 migration in the verdict.
- **Redundancy reduces boost.** If two sources cover the same domains from the same editorial angle, the one with less original reporting drops a tier. Don't give two centre-right broadsheets both Tier 1.
- **Non-English domestic sources get a boost premium in non-English countries.** For countries where the domestic-language media ecosystem carries signals that don't propagate to English-language outlets, domestic-language sources should be boosted at or above the level their English-language equivalents would receive. The pipeline's translation layer handles the language barrier; the Goggle's job is to ensure these sources surface.
- **Think tanks and analytical outlets earn boost through depth, not speed.** They won't break news, but their analysis provides the structural context the pipeline needs to interpret events. Tier 2 or Tier 3 depending on domain relevance.
- **Official government sources get belt-and-suspenders treatment.** Even though government sources are migrating to Layer 2 direct fetch, include them in the Goggle at Tier 2 as a fallback. If Layer 2 fetch fails for a cycle, the Goggle boost increases the chance that government content surfaces through Brave. This is redundancy by design.
- **Curation exclusions default to Neutral, not Discard.** The curation prompt excluded sources under a hard-filter model where exclusion meant invisibility. Under the Goggle model, previously excluded sources should be re-evaluated: most should be left neutral (organic ranking, may surface serendipitously); only those that would actively degrade result quality should be discarded.

### Evaluation Process

**Step 1: Assess each recommended source.** For every source on the current whitelist, determine:
- What is this source's unique signal contribution? (What does it provide that nothing else on the list provides?)
- Does the claimed domain coverage match reality?
- What structural role does it play in the country's information ecosystem?
- Assign a boost weight with reasoning.

**Step 2: Re-evaluate each notable exclusion.** The curation prompt excluded sources under a binary include/exclude model. Under the Goggle model, most exclusions should become Neutral (organic ranking) rather than Discard. For every excluded source, determine:
- Does the exclusion reason justify active `$discard` (would this source degrade result quality), or should it simply remain un-boosted at Neutral?
- Would promoting this source to a boost tier fill a structural gap?
- If promoted, which tier and why?

**Step 3: Identify missing sources.** Are there outlets not on either list that should be in the Goggle? Common gaps:
- The government's preferred outlet for managed leaks / policy kite-flying
- At least one outlet that functions as a genuine opposition voice
- The outlet that breaks defence/security news first in this country
- At least one source that captures policy-elite discourse (what decision-makers actually read)
- For non-English countries: domestic-language sources that carry signals not available in English
- Official government sources (press office, gazette, parliamentary record)
- At least one think tank or analytical outlet providing structural depth
- Wire services with strong local bureaus (Reuters, AFP, AP, or regional equivalents)

**Step 4: Identify discard targets.** Which outlets in this country's media landscape would waste result slots if they appeared? Tabloids, content farms, outlets that syndicate wire copy without adding value, sources with known misinformation patterns.

**Step 5: Validate query configuration.** Specify the Brave News Search parameters for this country and validate the curation prompt's existing localized query vocabulary:
- `country`: ISO 3166-1 alpha-2 code
- `search_lang`: Primary language(s) for queries (ISO 639-1). If the country's media ecosystem operates in multiple languages that carry distinct signals (e.g., India: Hindi + English + regional), list all relevant languages and note which domains each covers.
- Review the curation prompt's Localized Query Vocabulary for accuracy, staleness, and gaps. Flag terms that wouldn't work well as Brave News Search queries (too generic, too academic, ambiguous across contexts).
- Produce example query strings combining leader names with validated vocabulary terms.
